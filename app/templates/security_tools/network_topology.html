Network Topology & Traffic Flow

North–South: traffic enters/leaves the campus through the edge path (Internet → Firewall → Core).

East–West: inter-segment traffic is routed at the core (L3) between VLANs; policies differ per department.

Typical protocol mix (simulation)

  • IT / Admin: HTTPS, SSH, SMB, RDP (restricted at edge), DNS internal.
  • Finance / HR: encrypted SMB, M365-style HTTPS, limited peer-to-peer.
  • Smart Infrastructure: MQTT/CoAP toward controllers, camera RTSP isolated; correlates with IDS/SIEM views in the dashboard.

Security controls (narrative)

  • IT: server segment access; external RDP blocked by default.
  • Smart Infra: isolated VLAN; MQTT only to designated brokers.
  • Finance: strict RBAC; SMB signing / encryption enforced in policy view.

Simulated LAN: where events “move”

Security events, PCAP samples, and SIEM-style logs in this project represent traffic that would traverse the paths shown in Logical LAN: source IP → routed path → destination host in a VLAN. IDS and firewall pages apply policy checks on those logical paths.

  1. External → DMZ / edge: scanning and phishing-style events (threat intel, geo map) feed from SecurityEvent seed data.
  2. Lateral: host-to-host within or across VLANs appears in traffic analysis (Wireshark CSV) and exploit lab views as illustrative records.
  3. Real Nmap: when enabled, probes leave the machine running Flask toward the target CIDR you provide — this is separate from the 200 simulated assets.

This dashboard in the browser (HTTP)

Opening any page sends HTML from Flask. Interactive widgets issue fetch("/api/v1/…") on the same origin; Flask-Login uses the session cookie for GET/POST to the API.

Attack map: browser loads Carto basemap tiles (GET); event coordinates are computed server-side — no SIEM payloads are sent to the tile CDN.
